## 1. 기술 컨텍스트 — memory.md가 어떻게 쓰이나

### 1.1 주입 메커니즘
- `core/system_prompt_template.txt`의 `## User context` 섹션(`Current date and time` 아래)
  `{MEMORY_MD_INJECTION_POINT}` 자리에 memory.md 전문이 치환된다.
- 봇은 stateless API라 재시작하면 과거를 모른다. memory.md가 **항상 로드되는 장기 기억 L1**이다.
  (L2 = JSONL 아카이브, L3 = Notion.)
- 시스템 프롬프트에 `cache_control: ephemeral`이 걸려 캐시되지만, 본문이 길면 캐시 write 비용·
  컨텍스트 점유가 커진다 → **간결성이 곧 성능**.

### 1.2 이미 시스템 프롬프트가 처리하는 것 → memory.md에 **중복 금지**
`system_prompt_template.txt`를 먼저 읽어라. 아래는 이미 있으니 다시 쓰지 말 것:
- dual-response JSON 출력 형식, voice/text 분리
- **음성 말투 = 존댓말 `~어요/~네요` 고정** (운전 중 음성 UX 판단으로 확정됨), 1인칭 금지,
  헤지 금지, 주소 낭독 금지, 숫자 풀어쓰기
- STT 오인식 보정 규칙
- **소스 라우팅 판단원칙** (개인정보→Notion, 위치→Kakao, 영업시간·평점→Google Places,
  일반·최신→Brave web_search 1~2회 제한, 차량→Hyundai) ← Phase 7 ②번이 여기 이미 구현됨
- Notion data source 라우팅 + data_source_id 2종 (아래 2.4 재인용)
- 환각 금지

### 1.3 memory.md가 채워야 할 빈칸 (Phase 7 정의 기준)
`docs/implementation-manual.md` "Phase 7" 절이 요구하는 **사실 데이터**:
1. **사용자 프로필** — 이름/호칭, 차량(모델·연료종류), 자주 가는 목적지, 반복 맥락(인물·일정 패턴), 선호
2. **응답 개인화 힌트** — 시스템 규칙(존댓말 등)과 충돌하지 않는 선의 개인화 (호칭, 길이 감각,
   "하지 말 것")
3. **맥락 통합용 단서** — 반복 맥락(예: 정기적으로 함께 다니는 사람, 자주 가는 동네)을 명시해
   두면 장소 추천 시 분위기·동선을 엮을 근거가 된다 (Phase 7 ③의 입력).

## 4. 설계자가 내려야 할 열린 결정

1. **반복 맥락의 노출 범위 — 프로파일로 분기** ⚠️
   - 개인 반복 맥락(함께 다니는 사람, 집/동네 등)은 Phase 7 ③(특화 추천)의 핵심 입력이지만,
     **전시에서는 가려야 하고 실사용에서는 필요하다.**
   - 권장: memory.md의 민감 항목을 **개인용/전시용으로 분리**한다. 예) `core/memory.md`는
     실사용 전체본, 전시 데모에선 민감 줄을 제거한 버전을 주입(또는 프로파일 스위치).
     구현 방식은 사용자/봇 개발자와 협의. **memory.md 작성 단계에선 민감 항목을 명확히 태깅**해
     두면 나중에 가리기 쉽다.
2. **길이 예산**
   - 매 호출 주입 비용. 권장 상한 **30~50줄(대략 400~700토큰) 이내**. 넘으면 우선순위 낮은
     항목부터 잘라라.

> 말투(존댓말)·Obsidian 사용 여부는 **이미 확정**됐다. 음성=존댓말 고정(시스템 프롬프트가 처리),
> Obsidian은 현재 주요 도구. memory.md에 말투 지시를 다시 넣지 말 것.

## 5. 권장 memory.md 스켈레톤

```markdown
# 사용자 컨텍스트

## 기본
- 호칭: (봇이 사용자를 뭐라고 부를지 / 또는 호칭 없이)
- 차량: 현대 아반떼
- 소속: 연세대 UIC, CTM 전공 (2026-1학기 재학)

## 자주 가는 곳 / 반복 맥락   ← 민감 항목은 [개인전용] 태깅
- (집·학교·자주 가는 동네 — 사용자 확인)
- (반복 일정 패턴: 예) 매주 X요일 학교, 정기 미팅 등)
- [개인전용] (함께 다니는 사람 등 — 전시에선 제거)

## 관심사 / 진행 중
- car-assistant 차량 음성봇을 직접 개발 중
- (그 외 안정적인 관심사 1~2개 — 볼트/사용자 확인)

## 응답 개인화 힌트
- (시스템 규칙과 충돌하지 않는 선의 개인화. 길이 감각, '하지 말 것' 등)
```

> 스켈레톤은 출발점. **빈 항목을 추측으로 메우지 말 것** — 모르면 사용자에게 묻거나 비워라.
> 민감 항목은 `[개인전용]` 태깅해 전시용에서 쉽게 가릴 수 있게 한다.
