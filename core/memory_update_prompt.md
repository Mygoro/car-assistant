# memory.md 자동 갱신 루틴 (세션 종료 시 1회)

> **이 지시문은 봇의 매 호출 시스템 프롬프트에 주입하지 않는다.**
> 세션/하루 종료 후 야간 task(예: `core/archive.py`의 일일 Markdown 요약 직후)에서 **1회만** 실행한다.
> 이유: 갱신 로직은 종료 시 한 번만 필요한데, 주입 본문에 넣으면 매 음성 호출마다 토큰·지연을 낭비한다.
> (memory.md는 "사실"만 담는 lean 본문으로 유지하고, "언제·무엇을·어떻게 갱신하나"라는 동작은 여기로 분리.)

## 입력
- 그날의 대화 로그 (JSONL 아카이브)
- 현재 `core/memory.md` 전문

## 작업
그날 대화에서 **"스테이터스 변경"에 해당하는 안정적 사실의 변화만** 식별해 `core/memory.md`에 반영한다.

### 반영 대상 (안정적 사실의 변화)
- 호칭 변경
- 차량 변경 (모델·연료종류 등)
- 새로 생겼거나 바뀐 반복 목적지·정기 동선
- 정기 일정 패턴 변화 (운동 루틴 변경, 새 정기 미팅 등)
- 새 안정적 관심사·진행 프로젝트, 또는 명시적으로 종료된 항목
- 음식 선호·제약 변화
- 학기 전환에 따른 수업 요일·과목 갱신
- 주유 기준 변경 (예: "150km가 아니라 100km부터 넣어" 발화 감지 시)
- 운전 패턴 변경 (통학 요일 변경, 새 정기 이동 경로 등)

### 반영 금지
- 일회성 사건·약속 (개별 일정은 Calendar/Notion 소관)
- 휘발성 진행 상태 ("Phase X 진행 중" 류 — 박지 말 것)
- 그날의 잡담·단발 질의
- 말투·소스 라우팅 등 시스템 프롬프트가 담당하는 영역
- 여자친구 이름 (봇은 항상 "여자친구"로 호칭 — memory.md에도 이름 직접 기재 금지)

## 병합 규칙
- 기존 항목과 충돌하면 **교체**, 신규는 해당 섹션에 **추가**.
- 기존 사실을 근거 없이 삭제하지 않는다 (명시적 종료·변경만 반영).
- 민감 항목은 반드시 `[개인전용]` 태그를 유지하거나 새로 부여.
- 길이 예산 **≤50줄(~700토큰)** 유지. 초과 시 우선순위 낮은 항목부터 제거.
- 변경 후보가 모호하면 **보류** (대화에서 명시적으로 확인된 변화만; 추측 금지).
- 반영할 변화가 없으면 **아무것도 하지 않는다 (no-op)**.

## 출력
- 변경이 있을 때만 `core/memory.md` 전체를 재작성(전체 치환).
- 무엇을·왜 바꿨는지 **1줄 변경 로그**를 그날 daily 로그(또는 커밋 메시지)에 남긴다.
- 봇 재시작 시 다음 호출부터 갱신된 memory.md가 `{MEMORY_MD_INJECTION_POINT}`에 주입된다.

## 트리거 예시 (의사 흐름)
```
세션 종료 → 일일 요약 생성(기존 야간 task)
          → 이 루틴 실행: (대화 로그 + 현재 memory.md) 입력
          → 스테이터스 변경 후보 추출 → 병합 규칙 적용
          → 변경 있음? 예: memory.md 치환 + 1줄 로그 / 아니오: no-op
```
