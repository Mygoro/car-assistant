# car-assistant 시연 대본

전시일 2026-06-02(화) · 짝 문서: `roadmap.md`(설계), `booth-plan.md`(부스·운영)

세 가지 안: 메인(본인 시연) / 스트레치(방문자 호출) / 안전(영상+라이브 하이브리드).
OTTO 응답은 예시이며 실제 응답은 데이터에 따라 달라진다. 시점·타이밍 감각용 대본이다.

## 0. 엘리베이터 피치 (30초, 방문자 맞이용)

> "이건 차에서 손 안 대고 쓰는 음성 AI 비서예요. 폰을 꺼낼 필요 없이
>  'hey OTTO' 하고 부르면 일정도 알려주고, 차 상태도 확인하고, 메모도 해줘요.
>  운전 중에 폰 보는 게 위험하고 번거로워서, 제가 실제로 쓰려고 만들었어요.
>  Discord를 통해 음성이 오가고, 봇은 집 서버에서 돌아갑니다."

## 1. 메인 안 — 본인 시연 (3~4분 루프, 6시간 반복)

4스텝을 외워서 진행한다. 입력=폰(Discord 모바일, Krisp), 출력=노트북→스피커.

### Step 1 — 스케줄 조회 (P0)

- **사용자**: "hey OTTO" *(감지음/응답 시작 대기)* "오늘 일정 알려줘"
- **OTTO** *(필러: "잠시만요")*: "오늘은 오후 2시에 AI Agents 수업이 있고,
  노션에 적어둔 글쓰기 과제 마감이 오늘이네요."
- 소요: 약 8~15초 (MCP 읽기 포함)
- 폴백: 응답 없으면 "캘린더 연결을 확인하는 중이에요" → 재시도 1회 → 영상 모드

### Step 2 — 차량 데이터 질의 (P0)

- **사용자**: "hey OTTO 기름 얼마나 남았어?"
- **OTTO**: "현재 연료는 42퍼센트 남았고, 약 320킬로미터 더 주행할 수 있어요."
- 소요: 약 5~8초 (mock provider — 응답 결정적)
- 비고: exhibition 프로파일은 mock 백엔드. 응답값은 config 고정.

### Step 3 — 멀티턴 추론

- **사용자**: "hey OTTO 그럼 주유는 언제 하는 게 좋을까?"
- **OTTO**: "이번 주 안에 한 번 넣으시면 충분해요. 목요일에 수업 가시기 전에
  들르시는 걸 추천해요."
- 포인트: Step 1(일정)과 Step 2(연료)를 결합한 추론 → 히스토리 동작 시연
- 폴백: 맥락 누락 시 Step 1·2를 다시 발화해 히스토리 재구성

### Step 4 — 차내 캠 전환 (P1, 시간·여건 될 때만)

- **사용자**: "hey OTTO 차 안 좀 보여줘" → 노트북 화면을 차내 캠으로 전환
- 라이브가 안 되면 사전 녹화 주행 영상으로 전환 (티 안 나게)

## 2. 스트레치 안 — 방문자 직접 호출

exhibition 프로파일(쓰기 인텐트 off, 세션마다 히스토리 리셋). openwakeword는 화자 독립이라
방문자 음성도 인식된다. 봇은 OWNER 폰만 수신하므로 방문자가 본인 폰/헤드셋으로 말하면 동작.

**핵심: 이 시스템은 준비된 질문만 답하는 게 아니다.** 백엔드의 Claude가 등록된 툴로
툴 범위 안의 어떤 질문이든 답한다. 방문자에게는 "아무거나 물어보세요"로 안내한다.
예시 질문 카드는 제약이 아니라, 뭘 물어야 할지 머뭇거리는 방문자를 위한 마중물이다.

### 진행 순서

1. 헤드셋 전달 (일회용 커버 교체)
2. 동의 1줄: "음성은 저장하지 않습니다, 괜찮으실까요?"
3. 안내: "OTTO에게 아무거나 물어보세요. 다만 받아쓰기가 소음에 약하니
   또박또박 말씀해 주세요."
4. 방문자가 머뭇거리면 안내 카드 제시 (마중물):
   - "hey OTTO, 오늘 무슨 요일이야?"
   - "hey OTTO, 간단한 농담 하나 해줘"
   - "hey OTTO, 연세대학교는 어떤 학교야?"
5. OTTO 응답 → 방문자 반응 → 추가 질문 허용
6. 마무리 인사

진짜 병목은 Claude의 능력이 아니라 STT다 — 전시장 소음 + 낯선 발음/속도에서
받아쓰기가 틀리면 답도 틀린다. 그래서 "또박또박" 안내가 핵심이고, 인식이 실패하면
본인이 대신 발화해 복구한다. 실시간 정보(날씨·교통 등)는 웹 검색 툴이 전시 범위
밖이므로 일반 지식 질문 위주로 유도한다.

## 3. 안전 안 — 데모 영상 + 라이브 하이브리드 (폴백)

- 평소 노트북에 2~3분 데모 영상을 무한 루프 (자막 포함, 6/1에 로컬 저장 → 인터넷 불필요).
- 방문자가 오면 라이브 시도 → 실패 시 즉시 영상으로 설명 전환.
- 차내 캠도 동일: 지하 통신 되면 라이브, 안 되면 사전 녹화 주행분.
- 어떤 장애든 10초 안에 영상 모드로 후퇴할 수 있어야 한다.

---

## 4. 헤드셋 / 폰 / 스피커 구성 요약

| 안 | 입력 | 출력 |
|----|------|------|
| 메인(본인) | 폰 (Discord 모바일, Krisp 노이즈 억제) | 노트북 → 파워드 스피커 |
| 스트레치(방문자) | 폰에 연결한 헤드셋 (소음 격리) | 노트북 → 파워드 스피커 |
| 안전(영상) | 없음 | 노트북 → 파워드 스피커 |

노트북은 입력 마이크 비활성화(이중 캡처 방지), 폰은 스피커 출력 끔(에코 방지).

---

## 5. 시연 실패 시 멘트 모음

- 무응답: "지금 봇이 응답을 준비 중이에요. 잠시만요."
- 재시도 후에도 실패: "라이브 연결이 불안정하네요. 미리 녹화한 데모로 보여드릴게요."
- Wake word 미감지: "조금 더 또박또박 'hey OTTO'라고 불러주시겠어요?"
- 인식 오류: "제가 잘못 들었네요. 다시 한번 말씀해 주세요."

원칙: 당황한 티를 내지 않고 자연스럽게 영상 모드로 넘어간다. 폴백은 실패가 아니라
설계된 경로다.
